# Hogar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deudas por gasto con compensación automática, pantalla de inicio "Hogar", importador de Tricount y modo claro en el fork de SplitPro.

**Architecture:** El estado de las deudas se deriva con una función pura (`allocateDebts`) sobre los gastos existentes; los pagos siguen siendo gastos `SETTLEMENT` y solo se añade la tabla `SettlementTarget` para pagos dirigidos. La pantalla Hogar lee un grupo marcado (`Group.isHousehold`) y combina deudas + estadísticas puras (`householdStats`). El importador traduce la respuesta de la API no oficial de Tricount con funciones puras (`src/lib/tricount.ts`) y un cliente HTTP aislado.

**Tech Stack:** Next.js 15 (pages router), tRPC, Prisma/PostgreSQL, Tailwind 4, next-themes, next-i18next, Jest.

**Spec:** `docs/superpowers/specs/2026-10-12-hogar-design.md` · Diseño visual: `docs/DESIGN.md`

## Global Constraints

- Importes siempre `bigint` en unidades mínimas; mostrar con `getCurrencyHelpersCached(c).toUIString`.
- Condiciones Yoda, funciones flecha, métodos de iteración, imports ordenados (oxlint `sort-imports`) — ver `AGENTS.md`.

- Objetivos táctiles ≥ 44px, foco visible, `aria-*` en controles solo-icono.
- Prioridades (spec §1.4): 1 = `rent`, `mortgage`, sección `utilities` y sus elementos, `insurance`, o `recurrenceId` no nulo · 2 = `groceries`, `food` · 4 = `diningOut`, `liquor`, sección `entertainment` y sus elementos · 3 = resto.
- Saldar: sin importe libre; solo el deudor neto; total = suma de lo restante de las deudas elegidas.
- Tricount: única salida de red `https://api.tricount.bunq.com`; `transactionId = "tricount:<uuid>"`.
- Antes de cada despliegue: `pg_dump` en `/volume1/docker/splitpro/backups/` con permisos 600.
- Cada parte termina con `pnpm prettier --check . && pnpm lint && pnpm tsgo --noEmit && pnpm test && pnpm build --no-lint` en verde.

## Review Focus

- Un gasto apuntado por un pago se edita o borra después → el pago debe seguir cuadrando: el sobrante vuelve al reparto general (Task 1, test `targeted payment leftover goes to the pool`).
- Gastos negativos (devoluciones) → invierten el sentido de la deuda, no se ignoran (Task 1, test `negative expense creates a reverse debt`).
- Grupo con 3+ miembros o filas de otra moneda → solo cuentan las filas del par y la moneda pedida (Task 1, test `ignores third members and other currencies`).
- Reimportar el mismo tricount → no duplica gastos (Task 6, test `skips entries already imported`).
- Reparto de Tricount que no suma el total por redondeo → se ajusta al céntimo (Task 6, test `fixes rounding so allocations sum to the total`).

### Task 1: `allocateDebts` (lógica pura)

**Files:**
- Create: `src/lib/debts.ts`
- Test: `src/tests/debts.test.ts`

**Interfaces:**
- Produces:
  - `type DebtPriority = 1 | 2 | 3 | 4`
  - `debtPriority(category: string, recurring: boolean): DebtPriority`
  - `interface DebtExpense { id: string; paidBy: number; amount: bigint; currency: string; category: string; splitType: string; expenseDate: Date; createdAt: Date; recurrenceId: number | null; participants: { userId: number; amount: bigint }[] }`
  - `interface SettlementTargetRow { settlementId: string; expenseId: string; order: number }`
  - `interface DebtItem { expenseId: string; debtorId: number; creditorId: number; category: string; priority: DebtPriority; amount: bigint; covered: bigint; remaining: bigint; status: 'pending' | 'partial' | 'settled' | 'compensated' }`
  - `interface PairDebts { debtorId: number | null; creditorId: number | null; net: bigint; items: DebtItem[]; remainingByPriority: Record<DebtPriority, bigint> }`
  - `allocateDebts(input: { userA: number; userB: number; currency: string; expenses: DebtExpense[]; targets: SettlementTargetRow[] }): PairDebts`

Reglas del algoritmo (no las determina la firma):
1. Por cada gasto de la moneda con `paidBy ∈ {A, B}` y fila `r` del otro miembro del par: `r < 0` → el otro debe `-r` al pagador; `r > 0` → el pagador debe `r` al otro.
2. Deudor = quien más debe en total; `net` = diferencia (≥ 0). Si es 0, `debtorId = creditorId = null` y todo `compensated`.
3. Deudas del acreedor → `compensated` (covered = amount).
4. Filas a favor del deudor (lo que el acreedor le debe, incluidos `SETTLEMENT` pagados por el deudor): si son un `SETTLEMENT` con targets, su importe cubre esos gastos en `order`, hasta lo restante; el sobrante va a la bolsa. El resto, a la bolsa.
5. La bolsa cubre las deudas del deudor ordenadas por `(priority, expenseDate, createdAt, id)`, parcialmente.
6. `status`: covered = 0 → `pending`; 0 < covered < amount → `partial`; covered = amount → `settled`.

- [ ] **Step 1: Write the failing tests** (`describe('allocateDebts')`, helpers `expense({...})` con A = 1, B = 2, EUR):
  - `debtPriority`: `rent`→1, `electricity`→1, `utilities`→1, `insurance`→1, `groceries`→2, `food`→2, `diningOut`→4, `movies`→4, `entertainment`→4, `fuel`→3, `general`→3, `('groceries', true)`→1.
  - `rent paid by A, B owes 450; dinners paid by B 70 → rent partial, remaining 380, net 380, debtorId 2`.
  - `priority beats age`: cena (B debe 20, fecha anterior) + alquiler (B debe 450, posterior); B tiene 30 a favor → alquiler covered 30, cena covered 0.
  - `same priority oldest first`: dos supermercados B debe 40 (1 oct) y 40 (5 oct), 50 a favor → 40/10.
  - `credits above a debt settle it`: B debe 450 alquiler, B pagó 460 en cenas → debtorId 1 (A debe 10), deudas de B `compensated`.
  - `net zero`: debtorId null, todos `compensated`.
  - `targeted payment covers chosen debts first`: B debe alquiler 450 (prio 1) y cena 20 (prio 4); SETTLEMENT de B a A por 20 con target = cena → cena `settled`, alquiler `pending` 450.
  - `targeted payment leftover goes to the pool`: SETTLEMENT 100 con target = cena de 20 → cena settled, alquiler covered 80.
  - `negative expense creates a reverse debt`: gasto −30 pagado por A con fila B +15 → A debe 15 a B.
  - `ignores third members and other currencies`: filas del usuario 3 y gastos USD no afectan.
  - Invariante en todos los casos con deudor: `sum(remaining de items del deudor) === net`.
